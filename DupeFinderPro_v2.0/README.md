## 개요

DupeFinderPro는 파일 해시 기반의 중복 탐지와 규칙 기반 파일 분류(Organize) 두 가지 핵심 기능을 제공합니다.

- **중복 탐지**: 크기 → 부분 해시 → 전체 해시 3단계 필터링으로 빠르고 정확하게 중복 파일을 찾습니다.
- **파일 분류**: 사용자 정의 시나리오(규칙)에 따라 파일을 자동으로 이동·정리합니다.

## 주요 기능

### 중복 탐지

| 기능 | 설명 |
|------|------|
| 3단계 해시 필터링 | 파일 크기 → 부분 해시(앞 4KB) → 전체 해시 순으로 비교 대상을 좁힌다. 전체 비교는 크기와 앞부분이 모두 같은 파일만 하며, 앞부분을 읽다 파일 끝에 닿은 작은 파일은 그 해시를 전체 해시로 쓴다 |
| 병렬 해싱 | `Parallel.ForEachAsync` (MaxDegreeOfParallelism=4) |
| 클라우드 파일 스킵 | `FileAttributes.Offline` / `RECALL_ON_DATA_ACCESS` 속성 파일 자동 제외 |
| 같은 실제 파일 식별 | 볼륨 일련번호+파일 ID가 같은 경로(정션·하드 링크 등)는 한 번만 세고 결과 화면에 개수 표시. ID를 읽지 못한 파일은 비교하지 않음 |
| 검사하지 못한 파일 표시 | 읽을 수 없거나 클라우드에만 있거나 파일 ID를 확인하지 못한 파일은 중복에서 빼고 결과 화면에 목록으로 표시. 접근 권한이 없는 폴더 안의 파일은 목록에도 나오지 않음. 파일 접근 오류(IO·권한·보안·미지원 경로) 밖의 예외는 스캔 실패로 표시 |
| 항상 제외하는 폴더 | 휴지통(`$RECYCLE.BIN`), `System Volume Information`, 기본 격리 폴더, 격리 표식(`.dupefinderpro-quarantine`)이 있는 폴더 |
| 삭제 확인 | "중복 삭제"·"전체 적용"·파일별 "삭제" 모두 삭제하기 전에 확인 창 표시 |
| 마지막 사본 보존 | 삭제·격리는 그룹에 확인된 남는 사본이 있을 때만 실행 (파일별·일괄 모두 `CleanupOrchestrator` 한 경로). 남는 사본은 쓰기·삭제를 막은 채 열어 파일 ID가 지울 파일과 다르고 내용이 검사 때 해시와 같은지 확인하며, 처리가 끝날 때까지 잠가 둔다. 지울 파일도 잠근 채 내용이 같은지 확인한 뒤 연 채로 휴지통에 보낸다 |
| 실행 계획 | "중복 삭제"·"전체 적용"은 확인 창을 띄우기 전에 그룹별 계획을 확정하고, 동의하면 그 계획만 실행. 실행 중에는 입력이 잠기고 "처리 중단"으로 남은 파일을 멈출 수 있음 |
| 처리 결과 표시 | 성공만 "완료". 실패·건너뜀(파일 없음)·보류·취소는 이유와 함께 표시하고 다시 시도할 수 있음. "유지"는 선택만 바꾸며 파일을 잠그지 않음 |
| 작업 기록·되돌리기 | 모든 삭제·이동·격리·되돌리기 결과를 `%AppData%\DupeFinderPro\cleanup-log.jsonl`에 원래 경로·새 경로·해시와 함께 한 줄씩 기록. 이동·격리한 파일은 결과 화면의 "되돌리기"로 원래 위치에 돌려놓을 수 있음(원래 위치에 다른 파일이 있으면 덮어쓰지 않음). 휴지통으로 보낸 파일은 휴지통에서 복원 |
| 자동 보존 추천 | 처음에는 모든 파일이 "유지". "자동 선택"·"중복 삭제"를 누르면 `PriorityAutoSelectStrategy`의 추천 파일만 남기도록 설정 |
| 정렬/필터 | 낭비 공간·파일 수·파일명·크기 정렬, 확장자·최소 크기 필터. 그룹 목록은 화면에 보이는 것만 만든다(가상화) |
| 요약 갱신 | 처리할 때마다 중복 그룹 수·낭비 공간·삭제로 확보한 공간을 다시 센다. 이동·격리한 파일은 공간을 그대로 쓰므로 확보 공간에 넣지 않는다 |
| 이미지 미리보기 | 파일 클릭 시 우측 패널에 썸네일 표시 (jpg, png, bmp, gif, webp 등) |

#### 스캔 필터 옵션

- 포함/제외 경로 다중 지정
- 파일 타입 카테고리 (문서, 이미지, 동영상, 오디오, 압축파일, 설치파일, 기타)
- 확장자 화이트리스트/블랙리스트
- 파일명 키워드 포함/제외
- 최소/최대 파일 크기
- 생성일/수정일 범위
- 시스템 파일 제외, 재귀 탐색 옵션
- 빈 파일(0바이트) 포함 옵션 (기본 제외)

#### 중복 처리 액션

| 액션 | 동작 |
|------|------|
| 유지(Keep) | 해당 파일 변경 없이 보존 |
| 삭제(Delete) | 휴지통으로 이동. 확인 창을 거치며, 확인된 남는 사본이 있을 때만. 휴지통에 넣을 수 없는 위치(네트워크 경로 등)면 지우지 않고 보류하며, 그런 파일은 격리를 쓴다 |
| 격리(Quarantine) | 지정된 격리 폴더로 이동하고 폴더에 격리 표식을 남김. 삭제와 같이 격리 밖에 확인된 남는 사본이 있을 때만 |
| 이동(Move) | 사용자 지정 폴더로 이동. 원래 위치에 사본을 남기지 않아도 되며, 옮긴 파일은 그 위치에서 다시 확인될 때 같은 그룹의 남는 사본이 됨. 다른 볼륨이면 복사 → 내용 확인 → 원본 삭제. 원본과 같은 폴더·격리 폴더로는 옮기지 않음 |

## 빌드 및 실행

```bash
# 개발 실행
cd src/DupeFinderPro
dotnet run

# 릴리즈 빌드 (단일 .exe)
dotnet publish -c Release

# 인스톨러 생성 (Inno Setup 필요)
installer/build-installer.bat

# 검사 실행 (Windows, 종료 코드 0이면 모두 통과)
dotnet run --project tests/DupeFinderPro.Checks

# 실제 환경 검사 (subst·매핑 드라이브·UNC 별칭, 1GiB 파일, 다른 볼륨 이동과 중간 취소)
dotnet run --project tests/DupeFinderPro.Checks -- --env

# 탐지 성능 측정 (전체 해시 횟수·읽은 양·시간, 결과가 맞는지도 확인)
dotnet run -c Release --project tests/DupeFinderPro.Checks -- --perf
```

검사는 임시 폴더에서 정션·하드 링크를 만들고, 다른 볼륨이 있으면 그 볼륨의 사용자 임시 폴더로 이동도 시험한 뒤 지운다. 휴지통 삭제는 실제 휴지통 대신 임시 파일을 바로 지우는 대역으로 시험한다(휴지통에 넣을 수 없는 경로 항목만 실제 코드를 쓰며, 지우지 않으므로 흔적이 없다).

실제 환경 검사는 이 세션에만 쓰는 `subst` 드라이브와 `net use /persistent:no` 연결(`\\localhost\X$` 관리 공유)을 만들었다가 지우고, 1GiB 파일 2개를 임시 폴더에, 1개를 다른 볼륨(D: 또는 C:) 루트의 임시 폴더에 만들었다가 지운다. 관리 공유에 접근할 수 없거나 빈 드라이브 문자·다른 볼륨이 없으면 해당 항목을 건너뛴다.

빌드 결과물: `src/DupeFinderPro/publish/DupeFinderPro.exe`

## 아키텍처 원칙

- **DI 컨테이너**: `App.axaml.cs`에서 전체 서비스 등록 및 ViewModel 주입

- [ ] 휴지통 거부는 관리 공유(`\\localhost\F$`) 경로로만 실측함. USB·FAT 드라이브, 휴지통 용량보다 큰 파일, 볼륨별 "휴지통 사용 안 함" 설정에서의 동작은 확인하지 않음
- [ ] 휴지통에 넣을 수 없는 파일을 알고 영구 삭제하는 선택지는 없음 (지금은 보류하고 격리를 권함)
- [ ] 삭제 직전 내용 확인은 파일 크기와 관계없이 전체를 읽음(1GiB 2개 확인에 2.3초, 캐시된 상태 측정). 큰 파일을 격리·보류로 돌리는 선택지는 만들지 않았음. 느리면 "처리 중단"으로 멈출 수 있음
- [ ] 해시 캐시는 넣지 않음: 2GiB 재검사 1.7초, 작은 파일 4,000개 3.5초로 파일 열기 비용이 대부분이라 캐시로 줄일 몫이 작음(캐시도 파일마다 열어 확인해야 함)
- [ ] 디스크별 병렬 수 조정은 측정하지 않음 (해시는 고정 4개 병렬)
- [ ] 앱에는 격리 폴더 비우기 기능이 없음(비울 때 내용 확인도 없음). 이전 버전에서 만든 기본 위치 밖의 격리 폴더에는 표식이 없어 검사에 포함됨
- [ ] 휴지통으로 보낸 파일의 되돌리기는 앱에서 하지 않음 (Windows 휴지통에서 복원)
- [ ] `FormatBytes` 헬퍼 중복 (4곳) → 공통 유틸리티로 추출
- [ ] `DuplicateDetector` 해시 실패 원인 로깅 추가 (실패한 파일 목록은 결과 화면에 표시됨)
